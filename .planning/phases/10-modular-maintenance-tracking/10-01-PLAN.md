<feature>
  <name>Milestone engine: configurable thresholds, CSV write, urgency sort, DEFAULT removal</name>
  <files>app/maintenance/milestones.js, app/maintenance/milestones.test.js</files>
  <behavior>
    getDueSoonThresholds:
    - Returns {dueSoonMiles: 3000, dueSoonDays: 14} when no _config rows exist
    - Reads _config rows: Category="_config", Type="due-soon-miles" -> dueSoonMiles from IntervalMiles
    - Reads _config rows: Category="_config", Type="due-soon-days" -> dueSoonDays from IntervalDays
    - Handles missing/empty IntervalMiles/IntervalDays gracefully (falls back to defaults)

    isDueSoon:
    - Returns false when status is 'overdue' (overdue is not due-soon)
    - Returns true when nextDueMiles - currentMiles is within dueSoonMiles threshold
    - Returns true when nextDueDate is within dueSoonDays of today
    - Returns false when both are beyond threshold
    - Returns false when nextDueMiles is null and nextDueDate is null

    getMilestonesForCategory (modified):
    - Filters out rows where Category === '_config' before matching
    - Returns empty array [] when no CSV rows match AND no _config rows (not DEFAULT_MILESTONES)
    - Still works correctly when CSV rows DO match a category

    saveMilestoneConfig:
    - Calls downloadCSV to get fresh text+hash
    - Preserves _config rows from existing CSV
    - Replaces all non-_config rows with updatedRows
    - Calls writeCSVWithLock with merged rows
    - Updates state.fleet.milestoneConfig and milestoneConfigHash after success
    - Uses DI pattern (csvOps parameter)

    saveDueSoonThresholds:
    - Downloads fresh CSV
    - Removes old _config threshold rows (due-soon-miles, due-soon-days)
    - Adds new _config threshold rows with provided values
    - Preserves all non-threshold rows
    - Updates state after success
    - Uses DI pattern

    urgencyScore:
    - overdue returns lowest score (sorts first)
    - due-soon returns lower score than ok
    - ok returns positive score
    - not-tracked/no-interval returns highest score (sorts last)
    - Within overdue, more overdue (higher currentMiles - nextDueMiles) sorts first
    - Within due-soon, closer to due (lower remaining) sorts first
  </behavior>
  <implementation>
    1. Add imports: downloadCSV, parseCSV, serializeCSV, writeCSVWithLock, hashText from graph/csv.js
    2. Add getDueSoonThresholds() — reads _config rows from state.fleet.milestoneConfig, returns object with defaults
    3. Add isDueSoon(milestoneStatus, currentMiles, dueSoonMiles, dueSoonDays) — checks mileage remaining AND time remaining against thresholds
    4. Add urgencyScore(milestoneStatus, currentMiles, dueSoonMiles, dueSoonDays) — returns numeric sort key
    5. Modify getMilestonesForCategory: add .filter(r => (r.Category || '').trim() !== '_config') at top of csvRows; change the fallback from DEFAULT_MILESTONES lookup to return [] (keep buildDefaultConfigCSV using DEFAULT_MILESTONES for seeding only)
    6. Add saveMilestoneConfig(updatedRows, token, csvOps) — download-mutate-write pattern preserving _config rows
    7. Add saveDueSoonThresholds(miles, days, token, csvOps) — download-mutate-write replacing threshold _config rows
    8. Keep DEFAULT_MILESTONES export (used by buildDefaultConfigCSV for seeding) but remove it from getMilestonesForCategory fallback path
    9. Keep MILESTONES backward compat export

    For isDueSoon time check: compute days remaining as (new Date(nextDueDate + 'T00:00:00') - new Date(today + 'T00:00:00')) / (1000*60*60*24), return true if >= 0 and <= dueSoonDays. Accept optional `today` parameter for test determinism.

    For saveMilestoneConfig/saveDueSoonThresholds: use DI pattern `csvOps = defaultCsvOps` where defaultCsvOps = { downloadCSV, parseCSV, serializeCSV, writeCSVWithLock, hashText }. This is the established project convention (see record.js, batch-milestone.js).

    getDueSoonThresholds accepts optional `config` parameter (defaults to state.fleet.milestoneConfig) for testability without mocking state.
  </implementation>
</feature>
