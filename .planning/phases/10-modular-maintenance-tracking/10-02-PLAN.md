  <name>Task 1: Create settings.js view with milestone CRUD and threshold editing</name>
  <files>app/views/settings.js</files>
  <action>
    Create `app/views/settings.js` exporting `render(container)`.

    **Layout structure** (accordion by equipment type, per CONTEXT.md decision):
    - Back chevron link `[< Dashboard]` navigating to `#dashboard`
    - "Settings" heading
    - Auto-discover equipment types from `state.fleet.units` using `new Set(units.map(u => (u.Type || 'Other').trim()))` — filter out empty strings
    - For each type, render collapsible accordion section:
      - Type header (e.g., "Truck") with expand/collapse toggle
      - List of milestones for that type from `state.fleet.milestoneConfig` (filter out _config rows)
      - Each milestone row shows: Label, interval info (e.g. "30,000 mi" or "365 days" or "30,000 mi / 365 days"), [Edit] and [Delete] buttons
      - [+ Add Milestone] button at bottom of each type section
    - "Due Soon Thresholds" section at bottom:
      - "Miles before due" input, pre-filled from `getDueSoonThresholds().dueSoonMiles`
      - "Days before due" input, pre-filled from `getDueSoonThresholds().dueSoonDays`
      - [Save Thresholds] button

    **Add milestone flow** (inline form, not modal — per CONTEXT.md discretion):
    - Clicking [+ Add Milestone] shows inline form below the list: Label input, IntervalMiles input (optional), IntervalDays input (optional), [Save] [Cancel] buttons
    - Validation: Label required, at least one interval (miles or days) must be non-empty
    - On save: build row object `{Category: type, Type: slugify(label), Label: label, IntervalMiles: miles||'', IntervalDays: days||''}`, collect ALL non-_config rows from state.fleet.milestoneConfig, add the new row, call `saveMilestoneConfig(allNonConfigRows, token)`, show success toast, re-render settings
    - Type slug: lowercase label, replace spaces with hyphens, remove non-alphanumeric (e.g. "Engine Air Filter" -> "engine-air-filter")

    **Edit milestone flow** (inline form replacing the row):
    - Clicking [Edit] replaces that row with editable inputs for Label, IntervalMiles, IntervalDays, [Save] [Cancel]
    - On save: modify the row in the non-_config rows array, call `saveMilestoneConfig(allNonConfigRows, token)`, show success toast, re-render

    **Delete milestone flow:**
    - Clicking [Delete] shows confirmation "Delete [Label]?" with [Confirm] [Cancel]
    - On confirm: filter out the row from non-_config rows, call `saveMilestoneConfig(remainingRows, token)`, show success toast, re-render

    **Threshold save:**
    - On [Save Thresholds] click: validate miles > 0 and days > 0, call `saveDueSoonThresholds(miles, days, token)`, show success toast

    **Error handling:**
    - Wrap all save calls in try/catch, show error toast on failure
    - Use `getValidToken()` before each save operation

    **Styling:**
    - Use existing CSS variables (var(--bg), var(--bg-2), var(--text), var(--text-2), var(--border), var(--radius), var(--green-dark))
    - Follow unit-detail.js patterns for back link, section headers, input styling
    - Import showToast from unit-detail.js for feedback

    **Event wiring:**
    - Use event delegation on container with data-action attributes (project convention)
    - data-action="toggle-type", data-action="add-milestone", data-action="edit-milestone", data-action="delete-milestone", data-action="save-thresholds"
    - Use data-type for equipment type context, data-milestone-type for milestone identification
